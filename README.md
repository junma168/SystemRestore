# 系统复原工具 SystemRestore

重装系统前扫描本机所有软件与编程环境并生成清单；重装后只需运行本工具、点击"一键安装"，即可按清单复原整个开发环境。支持对清单逐项勾选、增删改，决定哪些要恢复、哪些不要。

- 纯本地运行，不联网上传任何数据
- 单个 exe，无需安装 Python 或第三方依赖（Python 源码方式运行同样零第三方依赖）
- 界面为本地 Web UI：启动后自动打开浏览器，所见即所得
- **本地安装包优先**：把下载好的 .exe/.msi 放进本地安装包目录，安装时直接本地运行，不联网、不依赖 winget 源
- **安装前自动比对新系统**：已经装过的软件不会重复安装
- **安装后自动配置环境变量**：Node/Python/Java/Go/Git 等目录自动补进用户 PATH、自动设置 JAVA_HOME，无需手动配置
- 扫描时自动排除系统自带组件（Edge、OneDrive、Windows 内置应用等）

## 一、使用流程

### 1. 重装系统前：扫描并保存清单

在旧系统上运行 `SystemRestore.exe`（或 `python run.py`），打开 **"① 扫描"** 页签：

- 选择扫描范围（默认全选，可按需跳过商店应用 / WSL / npm / pip / 配置备份）
- 选择清单保存位置（默认 `桌面\SystemRestore\scan-日期时间\manifest.json`；桌面下没有 `SystemRestore` 文件夹时会自动创建）
- （可选）把下载好的安装包（.exe/.msi）放进 **本地安装包目录**（默认 `桌面\SystemRestore\packages`），扫描时会自动关联——详见「本地安装包」一节
- 点击 **"开始扫描"**

扫描约需 1~3 分钟，产物有两部分：

| 产物 | 说明 |
|---|---|
| `manifest.json` | 软件清单：名称、版本、安装方式、安装目标、分类、是否勾选 |
| `configs/` | 配置备份：VS Code 设置、Git 配置、SSH 密钥、npm/pip 配置等 |

> **重要**：把 `manifest.json` 和 `configs/` 整个文件夹拷贝到 U 盘 / 移动硬盘 / 网盘。两者必须放在一起（`configs/` 相对于 `manifest.json` 定位），之后可以整体拷贝到新系统任何位置使用。如果用了本地安装包，`packages/` 文件夹也要一起拷贝。

### 2. 重装系统后：一键复原

在新系统上运行 `SystemRestore.exe`，打开 **"② 清单"** 页签：

- **打开清单**：选择之前保存的 `manifest.json`（想先熟悉界面的话，可以用 `examples/sample-manifest.json` 合成样例试手）
- 表格中逐项勾选/取消勾选，决定恢复哪些；支持搜索、按分类过滤、全选/反选
- 双击条目可编辑：改名、改版本、改安装方式与目标
- 右下角"新增条目"可手工添加清单里没有的软件
- 打开 **"③ 安装"** 页签，点击 **"开始安装"**

安装按依赖顺序自动执行：**运行库 → 开发工具（Git/Node/Python/Java/VS Code…）→ 应用 → 商店应用 → WSL → npm 全局包 → pip 包 → 配置文件恢复**。

**安装前会自动比对新系统现状**：工具先检测新系统里已经装了什么，清单中已存在的软件（版本相符）自动跳过、不再安装，安装表的"系统现状"列会标注每一项是"✔ 已存在"还是"未安装"。版本判定规则：

| 条目类型 | 判定规则 |
|---|---|
| Python / Java | 主、次版本都要一致（3.13 ≠ 3.12），否则安装清单指定版本 |
| Node / Go 等工具链 | 主版本一致即跳过（不把 22.22 降级回 22.14） |
| 普通应用软件 | 同名即跳过（不按版本降级重装） |
| npm / pip 全局包 | 按清单固定的版本，版本不符则装回指定版本 |
| VS Code | 本身已装则跳过，但扩展有缺口时会自动补齐缺失的扩展 |
| 配置恢复 / 手动安装项 | 总是执行 |

也可以随时点 **"检测系统现状"** 单独预览比对结果；确需重装某个已存在的软件，勾选 **"强制重装"** 再开始即可（命令行对应 `--force`）。

**安装结束后自动配置环境变量**：Node / Python / Java / Go / Git / VS Code / Rust / MySQL 等开发工具，光装上还不够——还要把它们的目录加进 PATH、设好 JAVA_HOME，才能在任意目录调用。工具会在安装结束后**自动**完成这些（只增不删，仅写入当前用户的环境变量，不动系统级设置），并对资源管理器广播变更，新开的终端立即生效。安装报告里会记录具体加了哪些目录、设置了哪些变量；之后若仍发现命令不可用，可点安装页的 **"补齐环境变量"** 手动补一次（会同时应用清单里记录的原系统 PATH 快照）。

安装过程中可随时停止；每一项的结果（成功/失败/需手动/已存在/跳过）实时显示，结束后生成安装报告。

## 二、安装方式说明

清单中每一项都带有安装方式，工具据此选择对应的安装通道：

| 方式 | 说明 |
|---|---|
| `winget` | 通过 Windows 包管理器安装（首选，自动选择 silent 参数） |
| `msstore` | 微软商店应用（winget msstore 源） |
| `choco` / `scoop` | 第三方包管理器（新系统上需先装好对应管理器，工具会提示） |
| `url` | 官方直链下载安装包 + 静默参数；无静默参数时下载后标记"需手动" |
| `npm` / `pip` | 命令行全局包 |
| `wsl` | WSL 发行版（`wsl --install`，需管理员） |
| `config` | 配置文件恢复（拷贝 + 旧用户名路径自动重映射） |
| `local` | **本地安装包**（.exe/.msi，见下节） |
| `manual` | 无可靠自动通道（安装包已被删除、绿色软件等），报告里给出提示，需手动安装 |

自动安装失败的条目不会中断整体流程，会跳过并继续，最后统一在报告和安装页列出。

### 本地安装包（有下载好的安装包时）

很多软件的安装包之前就下载好了（官网慢、winget 没收录、公司内部分发），重装后还要重新找一遍。可以把这些安装包集中放进一个文件夹，让工具直接本地安装：

1. 重装**前**：把 `.exe` / `.msi` 安装包放进本地安装包目录（扫描页可改，默认 `桌面\SystemRestore\packages`），然后正常扫描；
2. 扫描器会自动做两件事：
   - **按名称匹配**：安装包能对应上清单里某个软件的（如 `ChromeSetup.exe` ↔ Google Chrome、`node-v22.11.0-x64.msi` ↔ Node.js），给该条目打上 📦 标记——安装时**优先运行本地文件**，不联网、不依赖 winget 源；
   - **匹配不上**的安装包单独成为「本地安装包」条目（名称自动美化，如 `WeChatSetup.exe` → WeChat）；
3. 重装**后**：打开清单一键安装即可。带 📦 的条目如果本地文件找不到（忘了拷贝 `packages/` 文件夹等），会**自动回退**该条目原来的安装方式（winget / 直链等），不会阻断恢复；
4. 也可以随时在「② 清单」页双击任意条目，把安装方式改成「本地安装包」，点「浏览…」逐个指定文件。

安装规则：`.msi` 自动走 `msiexec /i /qn /norestart` 静默安装；`.exe` 默认加 `/S` 静默参数（NSIS 通用，覆盖大多数国产软件），个别安装器不识别时可在条目编辑的「静默参数」里修改。换机器使用时，只要 `manifest.json` 和 `packages/` 一起拷贝，安装包按文件名就能找到（查找顺序：清单记录的目录 → 清单目录 → 清单目录\packages → 清单上级目录 → 桌面\SystemRestore\packages）。

## 三、命令行用法（可选）

图形界面之外，所有功能都有对应的命令行入口，适合进阶用户和脚本化：

```bat
python run.py                        :: 启动 Web 界面（默认，自动打开浏览器）
python run.py --scan out.json        :: 扫描本机并保存清单
python run.py --install m.json       :: 按清单一键安装（自动检测新系统现状，已装的跳过）
python run.py --install m.json --force     :: 强制重装所有勾选项（跳过现状检测）
python run.py --install m.json --dry-run   :: 只打印将执行的命令，不实际安装
python run.py --selftest             :: 服务端冒烟测试
python run.py --port 8600            :: 指定 Web 服务端口
python run.py --no-browser           :: 不自动打开浏览器
python run.py --no-store --no-wsl --no-npm --no-pip --no-configs   :: 扫描时跳过对应项
python run.py --local-dir D:\packages    :: 指定本地安装包目录（默认：清单目录下的 packages）
python run.py --no-local                :: 扫描时跳过本地安装包目录
python run.py --with-inbox                                        :: 扫描时保留系统自带组件（默认排除）
python run.py --version              :: 显示版本
```

## 四、从源码运行

要求：Windows 10/11，Python 3.10+（仅用标准库，**零第三方依赖**）。

```bat
cd SystemRestore
python run.py
```

### 目录结构

```
SystemRestore/
├── run.py                  # 入口（CLI + 启动 Web UI）
├── make_icon.py            # 图标生成脚本（纯 Python 绘制）
├── build.bat               # 打包脚本（PyInstaller 单文件 exe）
├── sysrestore/
│   ├── model.py            # 数据模型：Item / Manifest / 分类 / 安装方式
│   ├── system.py           # Windows 交互：进程执行、.cmd 解析、PATH 刷新、UAC、桌面目录
│   ├── descriptions.py     # 常见软件/环境的中文用途说明库（自动匹配生成）
│   ├── scanner.py          # 扫描器：注册表/winget/choco/scoop/商店/开发环境/配置
│   ├── probe.py            # 新系统现状检测：安装前比对已装软件，已存在则跳过
│   ├── installer.py        # 安装引擎：多通道分发、顺序控制、失败隔离、报告
│   ├── webui.py            # 本地 Web 服务（http.server + JSON API）
│   └── web/index.html      # 单页前端（三页签 UI）
├── assets/                 # 图标（icon.ico / icon.png）
└── examples/
    └── sample-manifest.json  # 合成样例清单（演示格式，可直接打开试用）
```

## 六、常见问题 FAQ

**Q：清单里条目名称下方的小字是什么？**
那是**用途说明**——扫描时自动为每个条目生成的一句中文说明（这个软件/环境是做什么用的），时间久了不记得某个软件是干嘛用的，看一眼就知道。说明由内置的常见软件/环境库（数百条）自动匹配生成；双击条目可以修改，识别不出的条目会显示“用途未知”，也可自己补上。

**Q：怎么退出工具？关掉浏览器标签页就行吗？**
不行。本工具的界面是浏览器页面，exe 本身是后台进程——直接关闭标签页**不会**退出工具，进程仍在后台运行（关标签页时浏览器会弹确认框提醒）。彻底退出请点页面**右上角「退出工具」按钮**；也可以直接关闭启动时的命令行窗口或按 Ctrl+C。扫描/安装进行中时，「退出工具」会提示先停止或等待完成。

**Q：扫描结果准确吗？会不会漏软件？**
扫描覆盖注册表卸载信息（64 位 + 32 位 + 每用户）、winget/choco/scoop 列表、微软商店应用、Node/Python/Java/Go/Rust/.NET/Git/Docker 等命令行探测、VS Code 扩展、WSL 发行版、npm/pip 全局包，并自动去重合并。个别"绿色软件"（无安装信息、不在任何包管理器里）扫不到，可在清单页用"新增条目"手工补上。

**Q：新系统里已经装了一部分软件，会重复安装吗？**
不会。点"开始一键安装"时工具会先检测新系统现状：已存在的软件自动跳过（安装表"系统现状"列会逐项标注），只安装真正缺失的部分。判定规则见上文表格；想强制重装就勾选"强制重装"（或命令行 `--force`）。安装前也可以点"检测系统现状"单独预览。

**Q：Node / Python / Java 装好后命令不能用，还要手动配环境变量吗？**
不用。安装结束后工具会自动把这些开发工具的目录补进当前用户的 PATH，并自动设置 JAVA_HOME 等环境变量（只增不删，仅写用户级，不改系统级设置），新开的终端即可使用。个别安装器自身会改 PATH 的情况也不会重复添加。如果之后仍发现某个命令不可用，点「③ 一键安装」页的「补齐环境变量」即可（会同时应用清单里记录的原系统 PATH 快照）；改动对已经运行的程序无效，重启该程序即可。

**Q：我下载好了安装包，能让工具直接用本地文件安装吗？**
可以，这就是「本地安装包」功能。把 .exe/.msi 放进本地安装包目录（默认 `桌面\SystemRestore\packages`，扫描页可改）再扫描：能按名称匹配上已有软件的条目会打 📦 标记，安装时优先跑本地文件（不联网、不依赖 winget 源），本地文件找不到会自动回退原安装方式；匹配不上的安装包会单独成为「本地安装包」条目。也可以双击任意条目，把安装方式改成「本地安装包」并点「浏览…」逐个指定。详见「安装方式说明 → 本地安装包」一节。

**Q：Edge、OneDrive、Windows 内置应用怎么没扫进来？**这些属于**系统自带组件**——重装系统后新系统本来就有，默认自动排除，不记入清单（Edge WebView2 运行时例外：众多应用依赖它，会保留）。如确需保留某类系统组件，在扫描页取消勾选"排除系统自带组件"后重新扫描，或命令行加 `--with-inbox`。扫描完成后会提示本次排除了多少个系统组件。

**Q：为什么有些条目标记"需手动"？**
常见原因：① 安装来源已失效（winget 查无此包、下载链接 404）；② 该软件没有静默安装参数，自动安装会弹交互界面；③ 需要登录/许可钥的商业软件。安装报告里会给出具体原因和原始下载地址（如有）。

**Q：安装个别软件失败会打断全部吗？**
不会。失败项自动跳过并记录，后续项继续安装，最后在安装页和报告里统一列出，可对失败项单独重试。

**Q：需要管理员权限吗？**
扫描和大部分安装不需要。安装 WSL、部分系统级运行库时工具会弹 UAC 提权（仅该子进程）。建议右键"以管理员身份运行"以获得最全兼容性。

**Q：配置文件会恢复哪些？**
VS Code 用户设置与键位、Git 全局配置、SSH 密钥与配置、npm/pip 配置、Windows Terminal 设置等。恢复时会把旧用户名路径（如 `C:\Users\旧名`）自动替换为新系统当前用户名。密码、Token 类文件恢复后请自行确认是否需要重新登录。

**Q：清单可以跨电脑使用吗？**
可以。清单就是普通 JSON，`configs/` 用相对路径引用，整个文件夹拷贝到新机器任意路径都能打开。不同机器硬件/系统版本差异不影响清单结构，安装时逐项有兼容性回退（如指定版本不存在时自动装最新版）。

**Q：数据会上传吗？**
不会。工具完全本地运行，唯一的网络访问是向 winget/choco/npm/pip 及软件官网请求安装包本身。

## 七、已知限制

- WSL 发行版恢复需要新系统已启用 WSL 功能，且安装的是同一个发行版 ID
- 需要许可密钥的商业软件只能自动下载安装包，密钥需手动输入
- 扫描"每用户安装"的软件时以当前用户视角为准；换用户账号恢复时，该用户的软件清单需用对应账号重新扫描
